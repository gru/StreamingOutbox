# streaming-outbox

Сервис доставки outbox-сообщений из PostgreSQL 17 в Kafka: чтение через слот логической репликации (плагин pgoutput, Npgsql Logical Replication API — стриминг, без polling), публикация продюсером Confluent.Kafka, checkpoint позиции в служебном Kafka-топике `cdc-checkpoints` и подтверждение LSN только после подтверждённой доставки — at-least-once без потерь.

Архитектура и контракты — в `docs/` (главное: `docs/dependencies.md`, `docs/recommendations.md`, `docs/outbox-table.md`, `docs/metrics.md`); описание стенда и команд — `docs/stand.md`.

Конвейер доставки (задачи 1–5) замкнут: `чтение WAL → отправка в Kafka → ACK → durable checkpoint → подтверждение LSN`; устойчивость (задача 6) — переподключения с настраиваемым backoff, терминальные ошибки, корректная остановка в порядке «ACK → checkpoint → подтверждение → закрытие»; Recovery Mode (задача 7) — ручное аварийное восстановление на один старт (env `CDCOUTBOX__RECOVERYMODE=true`): старт от текущей позиции слота или пересоздание отсутствующего, новый checkpoint до начала чтения, пропуск окна — осознанный; idle-предупреждение (задача 8) — WARN в лог не чаще одного раза за `IdleTimeoutSeconds` (дефолт 30 с) при отсутствии новых outbox-сообщений, новое событие сбрасывает таймер; сигнал — риск накопления WAL: слот без событий не подтверждается, heartbeat-механизм отсутствует (сознательное решение — сервис рассчитан на постоянно пишущиеся outbox); метрики (задача 9) — полный аудит: 14 метрик metrics.md (в коде 13, `outbox_failovers_total` — с задачей 10), единый label `slot` = имя слота у всех, критерий нейминга `outbox_<подсистема>_<показатель>` зафиксирован в metrics.md; `outbox_saved_messages_total` из исходных условий не переносится — это метрика пишущей стороны (в контуре её закрывает `writer_messages_written_total` Writer). Следующая задача — 10 (Active-Passive: consumer group на `cdc-checkpoints`).
